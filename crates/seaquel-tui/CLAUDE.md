# seaquel-tui

Moved from the root `CLAUDE.md`, which has the overview and the crate map. "Above" and "below" may point at sections that now live in another `CLAUDE.md`.

- `seaquel-tui` — the `seaquel-tui` binary (phase 7a), a lazygit-style terminal client and its own release asset (`npm run tui:build`, `build-cli.mjs --bin seaquel-tui`); the app doesn't install it (the README gives a manual download). ratatui 0.30 over crossterm 0.29, `ratatui-textarea` 0.9 for the editor's buffer. `state/` is the model and a pure `update(&mut Model, Msg) -> Vec<Effect>` (no Core, I/O or clock); `view/` only reads the model; `runtime/` owns the terminal, the event loop, the Core calls (`runtime/core.rs`'s `Session`, as `Effect`/`Msg` pairs), the log and the state file. One keymap table (`state/keymap.rs`) drives the keys, the key bar and `?` help; the strings are in `state/text.rs` (English only). Options: `--project`, `--connection` (id, else exact name), `--theme dark|light`, `--no-mouse`, `--page-size N`, `--log-level`. It refuses to start unless stdin and stdout are terminals (crossterm would reopen `/dev/tty`, which macOS's kqueue can't poll).
  - **Data.** It opens the app's file as a second process (`second_process()`, so `RequireCurrent` and no maintenance writes) with `SecretWait` around the store and `with_external_changes(1 s)`, before the terminal is entered; a refusal is printed to stderr with exit 1 and the screen never taken, and `STORAGE_NEEDS_UPGRADE` names the TUI's version, since a hand-downloaded TUI can be newer than the app. Every write is a Core call with its origin, `tui-<8 hex>`: run history, applied changes' history, `savedQueryCreate`/`Update` (Ctrl+S), and a password the user ticked "Save password" for (`connectionUpdate` with the save flag and `SecretChanges`, only after that connect succeeded); no view state goes to `seaquel.db`. It skips its own `StorageChanged` (so it adds `done.history` and an apply's rows itself) and reloads what it shows on the rest and on `external`. Its view state is `<data_dir>/tui/state.json` (0600 in a 0700 `tui/`, written to a temp file and renamed 500 ms after a change and at exit, latest save wins, at most 32 MiB read): ids of the last project and connection, the panel tabs, the theme and the open query tabs, **with the text of every tab that differs from its saved query, unsaved SQL included**, up to 1 MiB a tab (a longer one comes back empty with a note). A saved query edited here isn't published to a shared project's repo (no `git`); the app's next sync writes it.
  - **Screens.** Panels 1–4 (the connection; tables and views from `schema_tables`; saved queries and history; the staged queue) and the main view: a table's Data grid (`table_page`, 100 rows a page, `/` filters the loaded page, `F` sets one server filter, `s` sorts), Structure, Indexes, Constraints and an approximate DDL; a staged change's Diff and SQL; query tabs with Results, Explain (a self-time tree) and Messages. Edits are always staged: each staging is a `plan_edits` call, and `c` commits through `apply_changes` with a `HistoryContext`, sending `confirmed` only when its dialog listed destructive statements. On a connection with the predefined `prod` label a commit, a destructive run and an ANALYZE of anything but a plain SELECT ask for `prod` to be typed. `:all` streams at most 100,000 rows, then cancels and says so.
  - **Keys and the editor.** Run is Ctrl+R (F5, and Ctrl+Enter where the kitty keyboard protocol is on, which the TUI turns on when the terminal answers), the statement at the cursor Ctrl+E (Alt+R and Normal mode's `R` too), Explain Ctrl+X, ANALYZE `:analyze` (Alt+X). No bar names an Alt key: macOS terminals type characters for Option by default. An Alt+character the context doesn't bind is read as Esc then the character (tmux's default 500 ms `escape-time` merges the two), except while the kitty flags are on. The editor starts in Insert mode; Esc gives a small Normal mode (`hjkl w b e 0 $ gg G dd yy p x u i a A I o O`, `:w :explain :analyze :all :ask :q`). Highlighting comes from `seaquel_sql`'s scanner with the connection's engine; completion lists panel 2's tables and, after `alias.`, that table's columns, read with `table_metadata` the first time they're needed (`schema_tables` lists none). Ctrl+O edits the tab in `$VISUAL`/`$EDITOR` through a 0600 temp file under `tui/`, the editor running as its own foreground job (Ctrl+Z inside it stops both). Bracketed paste and mouse capture are on (clicks select, the wheel scrolls; `--no-mouse` turns capture off). `NO_COLOR` draws with attributes only; truecolor only when `COLORTERM` says so.
  - **Keychain and SSH.** Connecting a row whose password isn't saved asks for it (masked, with a "Save password" box); a failed server connect offers to type it again. While a `SecretWait` call has been pending 250 ms a box says the system is asking (on macOS, maybe behind the terminal window), and Esc gives up (`SECRET_UNREADABLE`). `SECRET_STORE_UNAVAILABLE` makes it ask for what the store would hold, with saving off for the session. `UNKNOWN_HOST_KEY` opens a trust dialog with the host and the fingerprint, and Trust retries with `HostKeyPolicy::Trust(fp)`, so Core writes `~/.ssh/known_hosts`; `HOST_KEY_MISMATCH` has no Trust. Typed secrets are zeroised on drop, dropped on disconnect and never in `Debug`.
  - **Ask AI** (Ctrl+K, `state/ask.rs`) calls `ai_generate` with the request as typed (Core resolves its `@mentions`) and only inserts the answer. Ctrl+R in the popup runs it only when it is one statement, Core's read-only **token check** (`seaquel_sql::read_only`, with the connection's engine) passes, panel 1 is connected to the popup's connection and the cursor isn't inside a statement of the user's; it goes in as a statement of its own and runs as an ordinary editor run (`db.run` with `RunTarget::Current`), not in a read-only transaction, so what the token check misses runs with the connection's rights. Every test build wraps its model client in `LoopbackOnly` (`runtime/core.rs`).
  - **Logs** go only to `<data_dir>/logs/tui.log` (0600, `O_NOFOLLOW`, rotated at 5 MB with two kept; no log when the data dir doesn't exist), through `seaquel-terminal`'s filter with `rmcp`, `ratatui` and `crossterm` also held at WARN, at `warn` unless `--log-level` says otherwise. `log` records go through `runtime/logging.rs`'s `FileLogger` rather than `tracing-log` (which drops key-values), as `<time> LEVEL target: message key=value …` by the server's `format_record` rules (control characters escaped, a value with a space, `=`, `"`, `\` or a control character quoted, values cut at 128 bytes, the message at 1 KiB); `tracing` events go through the `fmt` layer into the same file. The command log on screen is never written anywhere.
  - **Exit.** `runtime/terminal.rs` lists every way the process ends and what restores the terminal (the guard, the panic hook, signals, Ctrl+Z, `$EDITOR`, a closed terminal, which exits 0 like SIGHUP). After the loop the state file is written (not after a crash), the runner's tasks are aborted, closing (`close_all`, then storage) gets at most `SETTLE_WITHIN` (6 s), and `settle` waits at most 6 s more for the cancels Core spawned, so any exit takes at most about 12 s. Nothing writes to stderr while the screen is up, and exit messages go through `say` (`writeln!`, errors ignored), since `eprintln!` panics on a closed terminal.
  - **Tests.** Render tests are `TestBackend` text snapshots in `tests/snapshots/` (`UPDATE_SNAPSHOTS=1`; its `README.md` lists the differences from the design); `tests/terminal.rs` runs the binary under `script`, and `tests/closed_terminal.rs` and `tests/mouse.rs` on a pty the test holds. Live tests make their tables through `testing/live.rs`'s `TableGuard`, which drops them even when the test panics. Test hooks, debug builds only: `SEAQUEL_TUI_TEST_SECRETS` (a `MemoryStore`, which also takes "Save password"), `_KNOWN_HOSTS`, `_ORIGIN`, `_PANIC`, `_DUCKDB_HELPER`, `_DUCKDB_RELEASES`. The pty tests (`duckdb_install.rs`, `mouse.rs`, `closed_terminal.rs`) wait on the rendered screen (`tests/pty/screen.rs`, a small grid over `anstyle-parse`), not on raw output, since ratatui redraws only changed cells. No `seaquel-mcp`, `seaquel-rpc`, `git`, `imports`, `license-*` or DuckDB library (CI's "Native binaries' dependencies" step).
  - **DuckDB** runs in the helper. A connect answered `ENGINE_NOT_INSTALLED` opens the install dialog (`state/install.rs`, `Modal::InstallDuckdb`) with the pending connect kept, typed secrets included: it looks up the status (`Unsafe` adds that an install makes the folder private again) and the size (`duckdb_helper_asset`, one metadata request; nothing is downloaded before Enter), asks ("a separate download of 11.5 MB", the version on a line of its own), then shows a progress bar; success connects again with the same pending connect, Esc at any step cancels the lookup or download (Core's future dropped, no `.part` left) and returns to the picker on that connection, and a failure is worded by code (`text::install_failure`: no network or proxy, not published for this version or platform, damaged, disk, unusable folder) with `r` repeating the failed step (none for `NOT_SUPPORTED`). A connect right after an install that is still refused (`Pending::after_install`) is a problem, "The DuckDB helper can't be used", never a second download. `ENGINE_UNAVAILABLE` offers Reconnect, not a download. `CONNECTION_CLOSED` from a call on panel 1's connection, matched by Core id (`connect::lost_by`; a run by `query::Op::core_id`, so a leftover run from an earlier connection can't close a new one), marks it closed and opens "The connection was lost" with Reconnect. An apply that fails with `CONNECTION_CLOSED` (an `Err`, or the failed change of an outcome) is the GUI's `interrupted`: what Core says ran leaves the queue, the rest stays unmarked as failed, the queue is marked (`Queue::mark_interrupted`), panel 4 says "! may be partly applied: check the data", and `c` on a marked queue asks first (`ConfirmRecommit`). A capped `:all` shows its time up to the stop. Quitting lets a helper that took `close` finish its checkpoint (the exit stays bounded).
