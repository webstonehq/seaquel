# seaquel-http

Moved from the root `CLAUDE.md`, which has the overview and the crate map. "Above" and "below" may point at sections that now live in another `CLAUDE.md`.

- `seaquel-http` — infra, native only (phase 6): `client.rs` (the HTTP client the license crate had: reqwest 0.12 with rustls, the OS and webpki roots built lazily with a fallback, so a broken OS certificate store can't panic at startup, extra roots from `NODE_EXTRA_CA_CERTS` through `load_extra_roots(path, activity)`, `HTTP(S)_PROXY`/`NO_PROXY`, and `proxy_plan`), `egress.rs` (`Egress::{Off, Public, Any}`, `Egress::parse`, the host check and the filtering resolver; `Refusal` surfaces as `AI_EGRESS_BLOCKED`) and `native.rs` (`NativeHttp`, `NativeHttpOptions`: `seaquel_ai::http::HttpClient` over reqwest, streaming bodies, the assistant's timeouts below, never a redirect). The `system-proxy` feature adds the OS proxy (the desktop, through Core's `ai-system-proxy`). Interfaces reach it only as `seaquel_core::ai::native` and through Core's DuckDB helper install. **`release_asset`** (feature `release-asset`: `flate2`, `sha2`, `tempfile`; only Core's `duckdb-helper-install` turns it on, so the web server doesn't link it) downloads and installs a gzipped release asset: `Fetcher::asset(version, name)` reads `v<version>`'s metadata from the `ReleaseSource` (`github()`; `new(api, download)` only in tests, debug builds and the `testing` feature) and takes the asset's size (at most 64 MiB) and `sha256:` digest; `Fetcher::install` makes the target's folders private, streams the body through a SHA-256 hasher and a gzip decoder into a 0600 `.seaquel-download-*.part` file in the version folder (at most 256 MiB unpacked, `ASSET_TOO_LARGE`), checks size, digest and the gzip trailer in that order, then `fchmod` 0700, `fsync`, rename, folder `fsync`, and writes the `<file>.installed` record the same way; `install_file`/`install_file_cancellable` take a file the user copied (`--from`) and its hash, gunzipping it if it starts with gzip's magic. Dropping the future deletes the `.part`; `.part` files older than 10 minutes (`STALE_PART_AGE`, a killed install's) are swept on the next install. **Folders** (`InstallTarget { root, folders, file_name }`): `root` is created 0700 if missing, must be this user's, and loses group and world write; each folder below is created 0700 or set to exactly 0700, must be this user's, and is opened `O_NOFOLLOW | O_DIRECTORY` and checked and `fchmod`ed through that handle top down, so a symlink anywhere from `root` down is `UNSAFE_FOLDER` with nothing written through it and another user's folder is refused, never tightened. On Windows (`seaquel_runtime::acl`, the same rule the start's check reads) a folder below `root` and the file get a protected DACL of the user and SYSTEM unless they already have exactly that (the file on its temporary name, before the rename); `root` keeps its DACL unless others may replace or rename in it, and is then repaired in place (every entry kept, the replacing rights taken out of others' allows, set protected); a link (a name-surrogate reparse point) or an owner other than the user, SYSTEM or Administrators is `UNSAFE_FOLDER`. An `UNSAFE_FOLDER` message says what to do: remove `bin/duckdb` in Seaquel's data folder and install again, or point `SEAQUEL_DATA_DIR` at a folder of your own. Folders an install made are removed again, deepest first while empty, when it fails, is refused or is dropped (`MadeFolders`); one that was there already, or holds anything, stays, and `root` is never removed. Under the pin (Core's `duckdb_helper_pinned`) `Fetcher::install` gets an `Asset` built from the pin and makes no metadata request, and a 404 from the download URL is `ASSET_NOT_FOUND` on either path (GitHub answers a missing release the same way there). `open_regular(path)` refuses anything but a regular file before opening it (`O_NONBLOCK` on Unix, checked again on the handle), so a FIFO can't block the blocking pool; `install_file_paced` is the copy with a pause per read, used only by the CLI's test hook. **Requests** carry only `User-Agent: Seaquel/<version>` and `Accept`; 15 s to connect, 60 s between reads, 60 s overall for the metadata (`METADATA_TIMEOUT`). Redirects are followed by hand, at most 5: every hop `https:` (plain `http:` to loopback only when the source itself is loopback, which also turns proxies off), and metadata hops only on the API's origin; else `REDIRECT_REFUSED` before connecting. Errors are `InstallError { kind, message }` with codes (`RELEASE_NOT_FOUND`, `ASSET_NOT_FOUND`, `DIGEST_MISMATCH`, `SIZE_MISMATCH`, `GZIP_ERROR`, `NETWORK_ERROR`, `UNSAFE_FOLDER`, `FILE_ERROR` with only the `io::ErrorKind`, `CANCELLED`, …) and name no URL or path (reqwest's errors are reduced to their kind; the `NODE_EXTRA_CA_CERTS` warning leaves the path out, `ShowPath::No`). On Windows the final rename is retried for about a second, and a rename over a running helper with the same SHA-256 counts as installed. `testing::MockReleases` is a loopback release server (stalls, cuts, lying lengths, redirects) for the install tests in Core, the TUI, the CLI and `src-tauri`.
