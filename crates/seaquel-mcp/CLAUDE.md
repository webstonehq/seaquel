# seaquel-mcp

Moved from the root `CLAUDE.md`, which has the overview and the crate map. "Above" and "below" may point at sections that now live in another `CLAUDE.md`.

- `seaquel-mcp` — the MCP server (rmcp 3.4.1), an interface library that only `seaquel-cli` may depend on (`INTERFACE_LIBS` in `check-crate-deps.mjs`). Eight tools, all read-only: `list_connections`, `list_schemas`, `list_tables`, `describe_table`, `run_query`, `explain_query`, `list_saved_queries`, `run_saved_query`. Errors are tool results with `isError: true` and `CODE: message`, never protocol errors. Since phase 6 the six connection tools are the assistant's registry with `Profile::Mcp`: `tools::on_connection` checks the connection, `max_rows`, a saved query's lookup, the tool's sharing and a saved query's parameters, connects on first use, then calls `seaquel_core::ai::tools::call`; the `#[tool]` methods take `seaquel_core::ai::tools::mcp::*` as their parameters, so rmcp still parses and lists them. `list_connections` and the gathering across exposed projects for `list_saved_queries` stay here. Names, arguments, schemas, results, messages and `INSTRUCTIONS` didn't change (`tests/tools.rs`, `tests/tool_schemas.rs`). Its rules:
  - **stdout carries JSON-RPC only.** Nothing may print to it; logs go to stderr. It has its own line transport (`transport.rs`) so a line that isn't JSON gets `-32700` with `"id": null` instead of rmcp's silence.
  - **Only the connections named with `--connection`/`--project`** (id, else exact case-sensitive name) are exposed, resolved once at startup (`exposed.rs`); with neither, none. No tool takes a connection string, host, path or driver. A connection's AI schema and data sharing flags (after the global default in `app_state`'s `aiSettings`: schema on, data off) gate the tools, re-read on every call.
  - **No writes**, to databases or to Seaquel's own files: queries go through `query_stream` with `read_only`, EXPLAIN through `explain_read_only`, storage is opened read-only, and known_hosts is never written. A write opt-in is a follow-up with its own review.
  - **DuckDB opens restricted** (`ConnectRequest::restricted`), in the helper (`seaquel-duckdb`; the CLI links no DuckDB), which opens it with `session.rs`'s `open`. The workspace `duckdb` dependency links `json` statically so the JSON functions work there; `icu` can't be linked from crates.io, so time zones and TIMESTAMPTZ arithmetic fail on the MCP server (pinned in `seaquel-engine-duckdb/tests/restricted.rs`).
  - **Limits** (`seaquel_ai::limits`): `max_rows` default 100, at most 1,000 (`DEFAULT_MAX_ROWS`, `MAX_MAX_ROWS`); an 8 MB fetch budget (`MAX_FETCH_BYTES`, Core's `max_bytes`); a cell's text cut at 64 KB (`tools::format::MAX_CELL_BYTES`, as a `{"truncated": true, "bytes", "text"}` object) and a result stopped before its JSON passes 4 MB (`MCP_RESULT_BYTES`); a 60 s timeout per call (`DEFAULT_CALL_TIMEOUT`, not counting a pending keychain prompt, `SecretWait`, in `seaquel-secrets` since phase 7a, counting `get`, `set` and `delete`). That `timed` deadline is the only one on an MCP call (`ai::tools::call` sets none; `ToolContext::timeout` is only the database's statement timeout, the call timeout). Past it the call's stream is dropped, which cancels it, and Core's `timeout` also stops the statement on the server (Postgres `pg_cancel_backend`, MySQL/MariaDB `KILL QUERY`, from a fresh connection).
  - Cells render like `$lib/values` `cellText` (`seaquel_ai::tools::format`): bigint and decimal as strings, bytes as `\x` hex, JSON through a `JSON.stringify` port; `null` stays `null`.
  - rmcp is held at WARN in the CLI's log filter (`log_filter_holding(level, &["rmcp"])`, phase 7a), so its DEBUG "received request" line, which carries each tool call's arguments and SQL, never reaches stderr, whatever `--log-level` says.
