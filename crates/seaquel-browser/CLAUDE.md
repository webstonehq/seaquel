# seaquel-browser

Moved from the root `CLAUDE.md`, which has the overview and the crate map. "Above" and "below" may point at sections that now live in another `CLAUDE.md`. The demo as a whole is in `src/lib/core/browser/CLAUDE.md`.

- `seaquel-browser` — the demo's Core in the page (phase 8), an interface crate (`browser-interface` in `check-crate-deps.mjs`: an interface's crates plus `seaquel-engine-duckdb`, no other engine). Every dependency but `log` is wasm32 only, so natively it is its log formatter and three tests, and `browser` is never unified into a native Core. It builds one Core with `ConnectPolicy::Unrestricted`, `WasmExecutor`, no limits, only `browser_engine(bridge)` and, when the page passes a fetch bridge, `ai_http(BridgeHttp)` with `AiEgress::Any` (`fetch.rs`: `start(id, method, url, headers, body) → Promise<status>`, `read(id) → Promise<Uint8Array | null>`, `abort(id)`; Rust picks the ids, a dropped send or body aborts, errors carry fixed text; without a bridge every `ai` call is `NOT_SUPPORTED`), and one workspace on `WorkspaceSpec::new("/demo").with_image(image)`. Exports (strings and bytes): `open(bridge, image?, onTrap?, fetch?)` → the commit counter (a second `open` closes the first Core), `call(body)` → `CoreResponse` JSON, `stream(body, onEvent)` → the event count, `events(onEvent)`/`unsubscribe(id)`, `snapshot()`, `commits()` and `ensureDemoConnection()`; the test build (`test-hooks`) adds `__test_trap`, `__test_call_as`, the dropped-call hooks and a second Core (`__test_side_*`). A refusal rejects with the `RpcError`'s JSON text; any other throw is a trap. A panic hook calls `onTrap` first (location only), since a panic in an async export leaves its promise pending. Every write carries the `demo` origin. `onEvent` and `onTrap` run while the module is mid-call, so they only queue work. Logs: WARN and above to `console.warn`/`console.error`, formatted as the server's (`log.rs`), never SQL or values. `build-wasm.mjs --module browser` builds it with the editor module's profile and wasm-bindgen, keeps `wasm-opt` only when it lowers the brotli size (it doesn't today), and refuses a module over 2,000,000 bytes brotli 11 (`BROWSER_BUDGET_BYTES`; `SEAQUEL_WASM_BUDGET_BYTES` overrides it to see the check fail) before replacing the package. `patchBrowserGlue` stamps every glue closure with the instance generation it was made in, so after `__seaquel_reinstantiate` a late callback meant for the dead instance does nothing, and records each `RuntimeError` thrown through the module's closures for `__seaquel_isCurrentTrap(e)` (an identity check, needed because WebKit's stacks name no module). The patch fails the build when the glue's shape changes.
