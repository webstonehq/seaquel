# seaquel-rpc

Moved from the root `CLAUDE.md`, which has the overview and the crate map. "Above" and "below" may point at sections that now live in another `CLAUDE.md`.

- `seaquel-rpc` — `workspace.rs` holds the workspace RPC: `Request`/`Response` (`CoreRequest`/`CoreResponse` in TS) with the `storage`, `library`, `settings`, `ui`, `shared`, `imports`, `db`, `ai`, `secret`, `ssh`, `git` and `license` groups, and `dispatch_workspace(core, ws, req, origin)`, whose `WriteOrigin` goes on the events of the writes it makes. The `library` group (`library.rs`) is unary and served on both transports: `connectionsList`, `projectsList`, `savedQueriesList {projectId}`, `queryVersionsList {projectId}`, `connectionCreate`/`Update` (with `secrets`, desktop only), `connectionRemove`, `projectCreate`, `projectEnsureDefault`, `projectUpdate`, `projectRemove`, `labelCreate`/`Update`/`Remove`, `savedQueryCreate`/`Update`/`Remove`, and since 5d-2 `projectSidebarGet`/`Set` and the dashboard, workflow and chat calls, each answering `Seqd` (a JSON body as `SeqdJson` in TypeScript). The `settings` group (`settings.rs`) and the `ui` group (`ui.rs`) are unary and served on both transports too. The `shared` group (`shared.rs`: `reposList`, `repoRegister`, `repoUpdate`, `repoRemove`, `linkProject`, `unlinkProject`, `unlinkPreview`, `scan`, `importProjects`, `sync`, `syncRepo`) and the `imports` group (`imports.rs`: `candidates`, `create`; the rpc feature `imports`) are unary and desktop only: `dispatch_workspace` answers `NOT_SUPPORTED` for both before Core is reached when `core.local_files()` is `None`, and the calls are boxed so a publish that falls back to a sync fits a 2 MiB stack (`library_calls_fit_a_2_mib_stack`). The storage group lost the library's loads and saves in 5d-1 (14 methods) 35 more in 5d-2 (`projectState*`, `appState*`, `dashboards*`, `dashboardVersions*`, `aiChats*`, `themes*`, `onboarding*`, `tutorial*`, `importState*`, `connectionOverrides*`) and `sharedReposLoadAll`/`SaveAll` in 5e; it keeps `queryHistory*`, `license*`, `vaultState*` and `userCredentials*` (13 methods). The retired methods' storage functions stay only for the frozen repo fixtures. Every group's params except `db`'s, and the request envelope, refuse unknown fields (`deny_unknown_fields`, `INVALID_ARGUMENT`); `db`'s params still ignore them, since its callers pass objects built from GUI state. The `db` group (`db.rs`) runs on the workspace's own connections: `connect` and `test` (`{target: {type: "saved", id} | {type: "form", form}, secrets?, trustHostKey?, createIfMissing?}`), `disconnect`, `query`, `execute`, `transaction`, `engine` (an `EngineRequest`, the dialect and introspection calls, run by `dispatch_on` on a `ConnectionHandle`; since 5c it has no `paginate` or `build*` calls, which Core now does itself), `planEdits`, `applyChanges`, `duckdbExtension`, `cancel`, `alive {connectionIds}` and `bindSaved {connectionId, savedConnectionId}` (records the saved connection a form connect opened before its row existed; once per connection, the same id again a no-op, another `INVALID_ARGUMENT`; it replaces the window's older connections for that id as a connect does). `connect`, `test`, `run`, `page` and the edit calls need the crate's `workspace` feature (on in `src-tauri`, `seaquel-server` and `seaquel-browser`; off in CI's bare `browser` clippy line), and answer `NOT_SUPPORTED` without it. The streams, `db.queryStream`, `db.run`, `db.page`, `db.tablePage` and `ai.chat`, are served only by `dispatch_stream`, which yields `CoreEvent`s (`{type: "stream", streamId, event}` for a query stream, `{type: "run", streamId, event: RunEvent}` for a run, page or table page, `{type: "ai", streamId, event: AiEvent}` for a turn; `StreamKind::of(group, method)` is the one list, behind `Request::stream_kind()`/`stream_id()`, and `CoreEvent::error(stream_id, kind, …)` makes a refusal of the right kind) and borrows the workspace for the stream's life; `dispatch_workspace` refuses them with `INVALID_ARGUMENT`. The `ai` group (`ai.rs`, the rpc feature `ai`): `chat` (stream only), and `respond`, `generate`, `models` and `test`, unary on every transport; without the feature they answer `NOT_SUPPORTED`. `TURN_STOP_WAIT` (`WRITE_WAIT` + 15 s, 45 s) bounds how long a transport polls a stopped turn for its reply's write before dropping it. `dispatch_workspace` boxes its `db` and `ai` arms (`Box::pin`), as it does the library, to keep its stack small. `RunParams`/`PageParams` `Debug` leave out the text, values and history context. `DbResponse` and `Response` are `Serialize` only. `workspace_events` turns the workspace's events into `CoreEvent::ConnectionClosed` and `CoreEvent::StorageChanged` (`{type: "storageChanged", kind, scope, ids, origin, seq}`). `ExecuteResult` and `StreamBatch` stay snake_case on the wire, as the TS reads them. Only the desktop serves the last four, each through its own function that needs no storage: `dispatch_secret` (the keychain; it names its own key forms, `db:`, `ssh:`, `ssh-key:` and `license-key`, and refuses `get`, `set` and `delete` of `ai-api-key:*` with `INVALID_ARGUMENT`, "managed by Core", on every transport), `dispatch_ssh` (Core's tunnels), `dispatch_git` and `dispatch_license` (the activation client). `dispatch_git(core, ws, git, req, origin)` takes an optional workspace: `pull`, `push`, `commit` and `resolveConflict` (`GitRequest::takes_repo_lock`) go through `Workspace::shared_git_*` when there is one with `LocalFiles` (so `lastSyncAt` is recorded), and otherwise take `core.repo_lock` themselves. `dispatch_workspace` answers `NOT_SUPPORTED` for SSH, git and license whatever the features, so `/rpc` on web can never open a tunnel, touch a repo or call the license server. Every variant exists in every build, so the generated TS doesn't depend on features. Both levels are adjacently tagged (`{"method", "params"}`, responses `{"method", "result"}`), and `method` must come before `params`: stored JSON columns are `RawValue` and stay byte-identical, so parse bodies with `parse_request` from the raw bytes, never through a `serde_json::Value`. A method with no params leaves `params` out (`{}` is refused). Errors are `RpcError { code, message, takenBy? }` (`takenBy` only with `NAME_TAKEN`). It logs the method name only, never params.
