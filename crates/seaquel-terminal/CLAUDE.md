# seaquel-terminal

Moved from the root `CLAUDE.md`, which has the overview and the crate map. "Above" and "below" may point at sections that now live in another `CLAUDE.md`.

- `seaquel-terminal` — what the terminal binaries share (phase 7a), an interface library in `INTERFACE_LIBS` that may use only `seaquel-core`, `seaquel-runtime` and `seaquel-types`: `APP_IDENTIFIER` and `data_dir()`, `duckdb_helper_dir()` (`seaquel_core::storage::data_local_dir(APP_IDENTIFIER)` + `bin/duckdb`), `core_builder(CoreOptions)` (Postgres, MySQL, SQLite and MSSQL natively, then `with_plugins(|id| id != "duckdb").duckdb_helper(DuckdbHelper { dir, version: VERSION })`, so `duckdb` is registered once, remotely; `Unrestricted`, `TokioExecutor`, optional `LocalFiles` and known_hosts; each binary adds its own extras, the CLI's import paths, the TUI's AI client; with no data-local dir and no override DuckDB isn't registered and a WARN says so), `CoreOptions::duckdb_helper_dir` (an override; the TUI's in-process tests pass a temp folder) and `with_hooks(&TestHooks)`, `TestHooks::from_env(prefix)` (debug builds only; `<prefix>_SECRETS`, `_KNOWN_HOSTS`, `_CALL_TIMEOUT_MS`, `_ORIGIN`, `_PANIC`, `_DUCKDB_HELPER`, a built helper hard-linked or copied into `<dir>/<VERSION>/` with 0700 folders, only when `duckdb_helper_dir` is overridden or `SEAQUEL_DATA_DIR` is set, else skipped with a WARN, and `_DUCKDB_RELEASES`, a base address such as `http://127.0.0.1:<port>` mapped to `ReleaseSource::new("<base>/api", "<base>/download")` for `CoreBuilder::duckdb_helper_releases`; `core_builder` ignores both fields in release builds), `log_filter`/`log_filter_holding` and `LogLevel` (the filter drops `sqlx::query`, `sqlx::postgres::notice`, tiberius's token stream and `sqlparser` at every level and holds the rest of tiberius, `russh` and `russh_keys` at WARN: russh's DEBUG lines name the SSH bastion and its host keys; `log_filter_holding` adds targets held at WARN, the CLI's `rmcp`), `ShutdownSignals`/`shutdown_signal`, `words.rs` (`host_key_fingerprint`, the `SHA256:…` after the last `Fingerprint: ` in an `UNKNOWN_HOST_KEY` message, and `destructive_reason`, a `DestructiveReason` in a few words; moved from the TUI for the CLI's prompts), and `VERSION`, `VERSION_TEXT`, `TERMS_LINE` (its `build.rs` reads the app's version). Its Core takes no default features: the four engines, `engine-duckdb-remote`, `storage`, `secrets`, `ssh`, `workspace`, and its own `duckdb-helper-install` feature (Core's, so reqwest; off by default, on in both binaries and in its own dev-dependency on itself); `imports` stays on the CLI and `ai-native` on the TUI.
