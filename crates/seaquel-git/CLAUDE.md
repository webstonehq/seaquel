# seaquel-git

Moved from the root `CLAUDE.md`, which has the overview and the crate map. "Above" and "below" may point at sections that now live in another `CLAUDE.md`.

- `seaquel-git` — shared projects' git over libgit2 (vendored): `Git`, with every call async over `spawn_blocking`. The home dir for default SSH keys is a field (`Git::from_env()` on desktop), so tests never read `~/.ssh`. The credential chain is agent, then the given key or the default keys, then user/password; it never hands out the same credential twice and gives up after 4, so a wrong password can't loop. A commit after a conflicted pull gets MERGE_HEAD as its second parent, and commit refuses while files are conflicted. A push the remote refuses fails with `PUSH_ERROR`; a non-fast-forward says `PUSH_REJECTED_NON_FAST_FORWARD`, which the TS matches exactly to mark the repo "behind". **A pull never overwrites local changes:** a fast-forward checks out with `CheckoutBuilder::safe()` before it moves the branch, and a merge that libgit2 refuses over local changes is refused too; both fail with `PULL_ERROR` "Commit or discard your changes to … first", naming at most ten paths as JSON strings (`PULL_REFUSED_LOCAL_CHANGES`; the GUI's `pull-error.ts` reads them). `resolve_conflict` and `resolve_conflict_deleted` (keep the side that deleted the file: the file goes and the deletion is staged) accept only a path the index holds as conflicted, relative, with no `..`, backslash, NUL or symlink on the way (`tree::check_resolvable`), and write through `tree`'s atomic no-follow write; anything else is `CONFLICT_ERROR`. `tree.rs` (5e) is the shared projection's file I/O: `scan`, `apply`, `restore`, `conflicted`, `project_dirs`/`project_dirs_listing`, under Core's file rules above. The crate depends on `seaquel-workspace` for those types.
