# seaquel-duckdb

Moved from the root `CLAUDE.md`, which has the overview and the crate map. "Above" and "below" may point at sections that now live in another `CLAUDE.md`. The driver side and the wire protocol are in `crates/seaquel-engine-duckdb/CLAUDE.md`.

- `seaquel-duckdb` — the DuckDB helper: `src/main.rs` and a `build.rs` that reads the app version from `src-tauri/Cargo.toml` (by `include!`ing `seaquel-terminal`'s parser, not depending on it). Its crate class is `ENGINE_HOSTS` in `check-crate-deps.mjs`: it may use `seaquel-engine-duckdb` (with `helper`) and the pure crates, and nothing may depend on it. `--version`/`-V` prints `seaquel-duckdb <version>`; any other argument, or a terminal on stdin, exits 2 ("seaquel-duckdb is started by Seaquel; it isn't run by hand"). **stdout carries frames only:** the binary keeps a duplicate of fd 1 for the frames and points fd 1 at stderr (`dup2`; on Windows also `SetStdHandle` and the CRT's `_dup2`), because DuckDB draws its progress bar on stdout (`fd_1_is_not_the_frame_channel`), and it turns `enable_progress_bar` off on every connection it opens. Nothing in it may `println!` except `--version`. stderr gets only a refusal or a panic's location. `helper::serve(input, output, version)` runs a reader thread, a dispatcher (hello, open, binds, the call registry, `cancel`, `credit`; never runs SQL, never waits for the output), a writer thread with a queue (control replies never wait; rows wait past 32 MiB queued; a call thread finding no one writing writes its own frames, flushing once per turn), the main session's thread (`query`, `stream`, `execute`, `transaction` in arrival order under a `blocking::Worker`), and one thread per read-only call on a clone, at most 16 at once (`MAX_READ_ONLY_CALLS`, then `TOO_MANY_REQUESTS`). Small results are held until `done` (schema plus up to 64 KiB of batches), so a `SELECT 1` is one write. `cancel` drops that call's `blocking::Call` guard (an interrupt only while that call holds its connection); a reused live call id is fatal. **Exit codes:** 0 when stdin ends, after `close`, or when stdout closes (`EPIPE`); 3 when the first frame isn't a `hello` with this protocol (after one `error` frame); 4 for a broken wire (an oversized frame, an unknown kind, bad JSON, a second `hello`, a reused id); 5 when frames have waited 30 s with none written (the wedge: a client that stopped reading, such as a TUI stopped with Ctrl+Z mid-stream; an idle connection survives any suspension). On an exit-0 end it waits up to 60 s (`SESSION_CLOSE_WAIT`, on tokio's clock) for DuckDB's connections to close, so the close checkpoint finishes, stopping early once the output has stayed busy for 500 ms; a refusal or broken wire waits 500 ms; a wedge doesn't wait. An error message is cut to 1 MiB. Built per target by `build-cli.mjs --bin seaquel-duckdb` (`npm run duckdb-helper:build`); `--gzip` also writes `<asset>.gz` (level 9, `gzipFile`, so Windows gets `seaquel-duckdb-<triple>.exe.gz`). `tests/bin.rs` runs the binary.
