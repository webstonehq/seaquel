# seaquel-secrets

Moved from the root `CLAUDE.md`, which has the overview and the crate map. "Above" and "below" may point at sections that now live in another `CLAUDE.md`.

- `seaquel-secrets` — `SecretStore` (`get`/`set`/`delete`), `KeychainStore` and `MemoryStore` for tests. `validate_key` allows only `db:<id>`, `ssh:<id>`, `ssh-key:<id>`, `ai-api-key:<id>` and `license-key`. The keychain service is `DESKTOP_SERVICE` (`app.seaquel.desktop`) in dev builds too, since changing it orphans saved passwords. Errors name the key, never the value. `SecretError::Unavailable` (`unavailable()`; the wire code stays `SECRET_STORE_ERROR`, and Core turns it into `SECRET_STORE_UNAVAILABLE` on a connect) is a store that can't be reached at all, read from keyring's boxed platform error: no D-Bus session bus, no `org.freedesktop.secrets` provider or a lost bus on Linux, `errSecNotAvailable`, `errSecNoSuchKeychain` or `errSecInteractionNotAllowed` (no GUI session, as over SSH) on macOS; a locked keyring, a dismissed prompt and a denied dialog stay refusals. The D-Bus names come from dbus's and keyring's sources, not a run on a headless host. `SecretWait` (`secret_wait.rs`, moved from `seaquel-mcp` in phase 7a; `seaquel_core::secrets::SecretWait`) wraps a store and times its calls, with a 5-minute limit: `get`, `set` and `delete` each count (a save into an item the app created reads it first, so it can show the macOS dialog too), `pending()`/`pending_for` and `changed()` (a `watch` that flips on 0↔1) let the TUI show its keychain box, and the MCP server's call timeout pauses while one waits. The web workspace has no store, so secret calls there are `NOT_SUPPORTED`. `ai-api-key:<id>` is written and read only by Core (the settings calls and the assistant); the `secret` group refuses it.
