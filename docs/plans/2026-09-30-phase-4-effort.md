## rmcp 3.4.1 API notes (for Task 6)

Features: the workspace entry is `default-features = false, features = ["server", "macros", "transport-io"]` (`server` pulls in `schemars`, `transport-async-rw` and `uuid`). seaquel-mcp's dev-dependency adds `client` and `transport-child-process`. rmcp logs through `tracing`; nothing reaches stdout unless someone installs a `tracing` subscriber that writes there, so the CLI's subscriber (if any) must write to stderr.

**Tools.** `#[tool_router]` on an inherent impl generates `Self::tool_router() -> ToolRouter<Self>` (options: `router = name`, `vis = "pub"`, `server_handler`, `allow_empty`; an impl with no `#[tool]` fn is a compile error). Each method is `#[tool(name = "...", description = "...", annotations(title = "...", read_only_hint = true))]`; the description defaults to the doc comment and the name to the fn name. Arguments come as `Parameters(args): Parameters<T>` with `T: serde::Deserialize + schemars::JsonSchema` (import `rmcp::handler::server::wrapper::Parameters`); doc comments on fields become schema descriptions, `Option<_>` fields are optional (`"type": [.., "null"]`), and the schema is draft 2020-12. Routers add: `Self::router_a() + Self::router_b()`.

```rust
use rmcp::{handler::server::wrapper::Parameters, model::{Implementation, ServerCapabilities, ServerConfig},
           tool, tool_handler, tool_router, ServerHandler, ServiceExt};

#[tool_router]
impl Server {
    /// Run a read-only query.
    #[tool(annotations(read_only_hint = true))]
    async fn run_query(&self, Parameters(a): Parameters<RunQueryArgs>) -> Result<String, String> { … }
}

#[tool_handler]              // fills in call_tool and list_tools from Self::tool_router()
impl ServerHandler for Server {
    fn get_info(&self) -> ServerConfig {
        ServerConfig::new(ServerCapabilities::builder().enable_tools().build())
            .with_server_info(Implementation::new("seaquel", seaquel_version))
            .with_instructions("…")
    }
}
```

- **`get_info`.** `ServerHandler::get_info(&self) -> ServerConfig` (`ServerConfig` = `InitializeResult`, `#[non_exhaustive]`, so build it with `ServerConfig::new(caps)` and `.with_server_info(..)`, `.with_instructions(..)`, `.with_protocol_version(..)`; `ServerInfo` is a deprecated alias). If omitted, `#[tool_handler]` generates one, but its `Implementation::from_build_env()` reports **rmcp's** crate name and version, so write it by hand (or pass `#[tool_handler(name = "...", version = "...", instructions = "...")]`). Default protocol version is `2025-11-25`; `2026-07-28` is known.
- **Tool errors (`isError`).** A tool returning `Result<T, E>` where both are `IntoCallToolResult` (`String`, `ContentBlock`, `CallToolResult`, `Json<T>`, …) maps `Err(e)` to a result with `isError: true` and `e`'s content; `Ok(CallToolResult::error(vec![ContentBlock::text(msg)]))` does the same explicitly. Returning `Err(rmcp::ErrorData)` is a **protocol** error, which hosts show opaquely: don't use it for Core errors. Verified: `Err("CODE: boom".to_string())` arrives as `{"content":[{"type":"text","text":"CODE: boom"}],"isError":true}`; arguments that fail to deserialize arrive as an `isError` result ("failed to deserialize parameters: missing field `text`"); an unknown tool name is a protocol error (`-32602: tool not found`). `rmcp::Json<T>` returns structured content with an output schema.
- **stdio transport.** `rmcp::transport::stdio()` returns `(tokio::io::Stdin, tokio::io::Stdout)`; `let running = Server::new(..).serve(stdio()).await?; running.waiting().await?;` returns a `QuitReason` when stdin closes. Needs a tokio runtime (the CLI's `#[tokio::main]`, with `rt-multi-thread`, `macros` and `io-std`).
- **In-process client over `tokio::io::duplex`** (tests/tools.rs): `let (s, c) = tokio::io::duplex(4096); tokio::spawn(async move { server.serve(s).await?.waiting().await }); let client = ().serve(c).await?;` (`()` implements `ClientHandler`). Then `client.list_all_tools().await?`, `client.call_tool(CallToolRequestParams::new("run_query").with_arguments(json!({..}).as_object().unwrap().clone())).await? -> CallToolResult` (fields `content: Vec<ContentBlock>`, `structured_content`, `is_error: Option<bool>`), `client.peer_info()` (`ServerPeerInfo`, whose `server_info` is an `Option<Implementation>`), and `client.cancel().await?` (the server's `waiting()` then returns `QuitReason::Closed`). `call_tool` drives MRTR `input_required` rounds; `call_tool_once` doesn't.
- **Child-process client** (tests/stdio.rs): `use rmcp::transport::{ConfigureCommandExt, TokioChildProcess}; let (transport, stderr) = TokioChildProcess::builder(tokio::process::Command::new(env!("CARGO_BIN_EXE_seaquel-cli")).configure(|c| { c.arg("mcp"); })).stderr(Stdio::piped()).spawn()?;` gives the transport plus `Option<ChildStderr>` (stderr is inherited unless set). `TokioChildProcess::new(cmd)` is the shortcut. `().serve(transport).await?` as above. To check that stdout carries only JSON-RPC, spawn the binary with plain `tokio::process::Command` and read stdout lines yourself instead.
- **schemars 1.** rmcp re-exports it as `rmcp::schemars` and uses `schemars::generate::SchemaSettings::draft2020_12()`. Derive with `#[derive(serde::Deserialize, schemars::JsonSchema)]` from the workspace `schemars = "1"` (the same 1.x crate in the lockfile); field attributes are `#[schemars(description = "...")]` or doc comments.
