# The tutorial

Moved from the root `CLAUDE.md`, which has the overview and the crate map. "Above" and "below" may point at sections that now live in another `CLAUDE.md`.

- **The web tutorial runs DuckDB-WASM in the page**, never on the server: the web build serves its own copy of the bundles (`duckdb-local-bundles.ts`, about 75 MB of assets, so an air-gapped install has a tutorial), the demo loads them from jsDelivr, and desktop uses SQLite through Tauri. The branch in `duckdb-bundles.ts` is on `import.meta.env.VITE_BUILD_TARGET` itself so Rollup drops the assets from the desktop and demo builds; keep it that way. `tutorial/database.ts` and `getDuckDBProvider` branch on the build constant too, so the desktop build has no DuckDB-WASM at all. The tutorial has its own provider and its own DuckDB: `DuckDBProvider` (`connect`, `disconnect`, `select`, `execute`; `select` and `execute` ignore parameters) over `tutorialDuckDb`, a separate `AsyncDuckDB` from the demo's `pageDuckDb` (`providers/duckdb-wasm.ts`), so Learn's tables never show in the demo connection and SQL in either can't drop the other's tables. Both start through `startDuckDb` (`duckdb-start.ts`), whose blob worker script (`duckdbWorkerScript` in `duckdb-bundles.ts`) silences the worker's console before `importScripts`, because DuckDB-WASM 1.32's worker `console.log`s every failing request with its SQL, whatever logger the page passes; failures still reach the page as rejected requests.
